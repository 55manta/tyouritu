調律ノート技術仕様2026-08-10

ひとつのコードから、iPhone と Android と Web へ

Capacitor で web 版をそのまま両ストアへ包む構成。データベース設計、認証、写真、オフライン、課金、国際化まで。あわせて、同時リリースの現実的な日程を示す。結論から言うと、Android は「すぐ」は出せない。律速は Google Play 側にあり、回避策がある。

先にいちばん重要な3つ

日程を決める要因

Google Play の個人開発者アカウントには、製品版を出す前に「12人のテスターが14日間連続でクローズドテストする」義務があります。2023年11月13日以降に作った個人アカウントが対象です。テスターは招待だけでは数えられず、実際にインストールした状態が14日continuousで必要。1人でも途中で抜けるとカウントがやり直しになります。

これに製品版アクセスの審査（最大7日）とアプリ本体の審査（新規アカウントは実績7〜14日）が続き、アプリ完成後さらに35〜45日かかります。Apple は90%が24時間以内なので、日程は完全に Android に握られます。

回避策

組織（法人）アカウントで登録すれば、この要件は丸ごと免除されます。12人×14日も、製品版アクセスの審査7日も不要で、いきなり製品版を出せます。法人確認に D-U-N-S 番号の取得（約14日）が要りますが、14日 < 21日＋運用の手間なので、法人格を使えるなら圧倒的に有利です。3〜4週間の短縮になります。

いま手配が要る

iOS のビルドには macOS が必須です。Xcode が macOS でしか動かないため回避できません。現在のご使用環境は Windows 11 なので、Mac 実機か、クラウドビルド（Ionic Appflow / GitHub Actions の macOS ランナー）の手配が最優先タスクになります。しかも Capacitor 8 は Xcode 26 を要求するため、Mac の OS バージョンも確認が必要です。

要点は、Web のコードが3つの出口すべてを兼ねることです。調律師が使うアプリ本体は iOS・Android のストアアプリとして、お客様が開く予約ページは認証不要の Web ページとして、同じコードから出せます。お客様に年1回のためにアプリを入れてもらうのは無理なので、この二面性は必須です。

2なぜ Capacitor か

選択肢ワンソースいまのモックを活かせるかWeb版も出せるか判断
Capacitor○○ ほぼそのまま○これを採用。Web の資産をそのまま両ストアへ。ネイティブ機能はプラグインで足す
Flutter○× 全面書き直し△動きは最も滑らかだが、HTML/CSS の資産を捨てることになる
React Native○× 全面書き直し×Web が出せない。お客様用ページを別に作る必要が生じる
PWA だけ○○○ストアに載らず検索流入がゼロ。iOS のプッシュは「ホーム画面に追加」した人にしか届かない

PWA だけで済ませる案は、課金アプリでは現実的ではありません。理由は3つ。iOS のプッシュ通知がホーム画面追加済みの人に限られて実効リーチが数%に落ちること、ストアの検索という無料の集客路を失うこと、Apple/Google 決済の信頼感が使えず定期課金の成約率が落ちることです。
ただし 「まず PWA で検証 → 手応えが出たら Capacitor でストアへ」という2段構えは、コードを流用できるので合理的です。

審査で気をつける点

Apple のガイドライン 4.2 は「Web サイトを包んだだけ」のアプリをはじきます。カメラ・プッシュ通知・オフライン動作といったネイティブ機能を実装し、審査メモで明示してください。Capacitor アプリのリジェクト理由として最も多いところです。

create table record_works (   -- 追加作業（整調・弦交換…）

設計上のいちばんの勘所

records.kind と pianos.last_tuned_on の関係です。周期を進めてよいのは kind = 'tuning' のときだけ。修理で伺った記録が周期を書き換えてしまうと、まだ調律していないピアノが1年先まで一覧から消えます。ここはデータベースのトリガーで守るのが安全です。

5個別の設計

認証 ── パスワードを持たない

メールに届くリンク（Magic Link）か6桁コードで入ります。パスワードを保存しないので、パスワード漏洩という事故そのものが起きません。ストア決済を使うのでカード情報も持ちません。守るべきものを減らすのが、1人で運営するときの最大の防御です。

写真 ── 撮ったら小さくして、期限を切る

  • 撮影後、端末側で長辺1280px・WebPに縮めてから送る。通信量と保管費の両方が下がります
  • Supabase Storage の非公開バケットに保存し、お客様への共有は有効期限つきの署名URLで渡す
  • photo_consent が false のお客様は、端末内にだけ置いてクラウドへ上げない
  • 保存期間（例：3年）を過ぎたものは定時処理で自動削除。持ち続けるほどリスクだけが増えます

オフライン ── 読めれば足りる

前回の判断どおり、深追いしません。当日の訪問先・お客様情報・前回の記録を IndexedDB に置き、写真とメモは端末に貯めて後から送る。ここで打ち止めにします。業界最大手の同種サービスでも閲覧キャッシュ止まりであり、双方向同期は実装の重さに見合いません。

プッシュ通知 ── 判定はサーバー、端末は受けるだけ

-- Supabase の定時処理（毎朝6時）
select p.id, c.name, p.last_tuned_on
from pianos p join customers c on c.id = p.customer_id
where c.deleted_at is null
  and (p.last_tuned_on + (p.interval_months || ' months')::interval) <= now()
  and p.reminded_cycle is distinct from /* 今回の周期 */ ...
-- 該当する調律師に「◯件のご案内時期です」を1通だけ送る

1台ごとに通知を送ると、うるさくて切られます。1日1通、まとめてが原則です。Android 13 以降は通知権限を明示的に求める必要があるので、初回起動ではなく「最初のご案内が出たとき」に求めます。

お客様用ページ ── 認証なしの公開ルート

お客様に年1回のためにアプリを入れてもらうのは不可能です。ご案内メッセージのリンクから開く /b/{token} は、ログイン不要の Web ページにします。トークンは推測できない長さで、有効期限を持たせます。ここで日付を選ぶと第2層の予定が生まれ、「今回は見送る」を押せば cust_skipped_cycle が立ちます。

日本の外部決済について。2025年12月にスマホソフトウェア競争促進法が全面施行され、アプリ内から外部決済へ誘導できるようになりました。ただし報道ベースの料率は、外部決済の組み込みで Apple 約21%・Google 約26%、リンク設置で15〜20%＋決済代行3%。ストア内課金の15%より高くつきます。0%になるのは「リンクを一切置かず文章で案内するだけ」という成約率が壊滅する方式のみ。個人開発の規模では、素直にストア内課金を使うのが最適解です。

国際化 ── 何を外に出すか

  • すでに終わっているもの：住所の構造、通貨表示（Intl.NumberFormat）、基準ピッチの初期値、未調律期間の割増のオン/オフ、税の呼び方
  • これからやるもの：画面の文言の外出し。t('home.title') 方式で JSON に切り出し、まず日本語と英語。量は多いものの機械的な作業です
  • 日付は Intl.DateTimeFormat へ。「2026年8月10日」は日本語固有の表記です
  • 敬称（「◯◯ 様」）と姓名の順序はロケール側で組み立てる。氏名は1フィールドのままにします

6Android と iOS で、それぞれ気をつけること

Android

戻るボタン。Android には物理的な戻る操作があります。シートが開いているときは閉じるだけにして、アプリごと終了しないよう @capacitor/app の backButton を必ず握ってください。ここを忘れると「入力中に戻ったら全部消えた」という最悪の体験になります。

Android

WebView のバージョン。いまのモックは color-mix() を22箇所使っており Chrome 111 以降が必要です。端末の System WebView が古いと色が落ちます。PostCSS で自動的にフォールバック色を生成すれば解決します。コードの書き換えは不要です。

Android

通知権限。Android 13 以降は POST_NOTIFICATIONS を実行時に求める必要があります。初回起動でいきなり出すと拒否されやすいので、最初のご案内が出るタイミングまで待ちます。

Android

画面幅 360px。各年代で最も多い機種は AQUOS です。実機で1度は目視してください。静的な監査では固定幅もタップ領域の不足も見つかりませんでしたが、実際の折り返しは実機でしか分かりません。

iOS

Xcode 26 が必須です。2026年4月28日以降、App Store Connect への提出は iOS 26 SDK でのビルドが必要になりました。Capacitor 8 の要件と一致しています。古い macOS では Xcode 26 が入らないため、Mac の OS バージョンから確認してください。

iOS

スワイプで戻る操作とセーフエリア。Web の挙動と違うため CSS の調整が必ず要ります。env(safe-area-inset-*) は対応ずみですが、キーボードが出たときの入力欄の押し上げは実機で確認が必要です。
